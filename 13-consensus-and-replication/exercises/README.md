# 第13回 演習

すべて Go(標準ライブラリのみ)。5本は、1つのモジュール(`ex13cr`)にまとめてある。macOS(Apple Silicon)で動作を確認した。**Linux での実行は未確認**。

```bash
cd 13-consensus-and-replication/exercises
go run ./ex1_paxos
go run ./ex2_raft
go run ./ex3_two_phase_commit
go run ./ex4_replication_latency
go run ./ex5_crdt
```

| 演習 | 実体 |
|---|---|
| ex1 | **離散イベント・シミュレーション**。単一値の Paxos と、規則を外した、2 つの壊した版 |
| ex2 | **離散イベント・シミュレーション**。Raft(リーダー選出、ログの複製、commit)と、4 つの安全性の検査、2 つの壊した版。**この回の、中心の演習** |
| ex3 | モンテカルロ。2PC のブロッキングと、原子性 |
| ex4 | モンテカルロ。チェーン、多数派、全員の ack の、書き込みの遅延 |
| ex5 | シミュレーション。CRDT の収束と、素朴な設計の失敗 |

**実際のネットワーク、実際のディスク、実際の Paxos・Raft の実装は、使っていない**。数値は、モデルの結果であり、傾向を見るもの。

## 進め方

第1〜12回と同じ。実行前に予想を書き、実行して比べ、外れたら理由を調べる。

**この回の、特別な進め方: 壊してみる**。アルゴリズムの**規則を 1 つ外し**、**何が壊れるか**(または、壊れないか)を、見る。**壊れたときに、検査器が、それを検出できるか**が、検査器の信頼性。

**注意**: ex2 は、2 秒ほどで終わる。ex1 は、数秒。他は、数秒以内。

## 演習1: Paxos

[ex1_paxos/](ex1_paxos/)

**課題**

1. 正しい版が、2,000 回、安全であることを、確認せよ。壊した版(a)(受理済みの値を無視)、(b)(再起動で状態を忘れる)が、**何回**、破れるかを、予想し、確かめよ。
2. (b) が、**まれにしか**破れない理由を、考えよ。アクセプタの、クラッシュの頻度を変えて、**破れる割合**が、どう変わるか、調べよ。
3. **敵対的なスケジュール**(2 人のプロポーザが、交互に、割り込む)を、**決定的に作り**、**活性が、失われる**(デュエリング)ことを、確かめよ。**ランダムなバックオフ**で、解決することを、確かめよ。
4. **発展**: 複数の値(ログ)に、拡張せよ(Multi-Paxos)。リーダーが、フェーズ 1 を、1 回だけ行う、最適化を、実装し、**メッセージ数**が、どう減るかを、測れ。

## 演習2: Raft

[ex2_raft/](ex2_raft/)

**課題**

1. 選挙タイムアウトの範囲を変えて、**新しいリーダーが決まるまでの時間**と、**選挙の回数**を、予想し、確かめよ(A)。
2. 障害の注入で、**正しい版が、4 つの性質を、破らない**ことを、確認せよ(B)。
3. **壊した版 C2**(選挙の制限なし)が、**検出される**ことを、確認せよ。検出された、**最初の違反**を、印字して、**何が起きたか**を、時系列で、説明せよ。
4. **壊した版 C1**(Figure 8 の規則を外す)は、ランダムな障害では、**検出できなかった**。**Raft の論文の Figure 8 の、シナリオ**を、**決定的に**作り(ノード S1〜S5 の、リーダー交代の順序を、固定)、C1 で、**違反が、起きる**ことを、確かめよ。**正しい版では、起きない**ことも、確かめよ。
5. **ディスクの永続化**を、モデルに入れよ(`votedFor` と term の書き込みを、**クラッシュの前に、失う**ことがある)。**どの規則が、破れる**か(選出の安全性)。
6. **スナップショット**、または、**メンバーの変更**(1 台の追加)を、実装せよ。**発展**。

## 演習3: 2PC

[ex3_two_phase_commit/](ex3_two_phase_commit/)

**課題**

1. クラッシュの時点(4 つ)ごとに、**ブロックする**、**しない**を、表にせよ(本文 §7.3)。
2. コーディネータの**復旧時間**の分布を、変えて、**ロック保持の最大**が、どう変わるかを、調べよ。
3. **協調的な終了**(参加者同士が、問い合わせる)が、**どの場合に、解決**し、**どの場合に、解決しない**かを、**参加者の状態**から、導け。
4. **発展**: 3PC を、モデルに入れ、**ネットワークの分断**が、あるとき、**原子性が、破れる**ことを、確かめよ。

## 演習4: 複製の遅延

[ex4_replication_latency/](ex4_replication_latency/)

**課題**

1. 停止の確率 q を、0、1%、5% と変え、方式ごとの、p99 を、予想し、確かめよ。
2. **q = 1% で、差が、小さかった**理由を、確率の計算(N = 3 のホップ数、停止に当たる確率)から、**解析的に**、説明せよ。
3. **停止を、ノードごとに、相関させる**(あるノードが、連続して、遅い)モデルに、変えて、結果が、どう変わるか。
4. **発展**: **読み**の遅延と、**スループット**(帯域)を、モデルに入れ、チェーンの、利点を、確かめよ。

## 演習5: CRDT

[ex5_crdt/](ex5_crdt/)

**課題**

1. G-Counter、PN-Counter、OR-Set、LWW-Register の、**merge の 3 つの性質**を、確認せよ。**LWW-Register で、同じ(時刻、レプリカ)から、異なる値が来る**と、何が、壊れるか(最初のバグ)。
2. **削除勝ち**の集合(追加と削除が、並行なら、削除が勝つ)を、実装し、OR-Set と、**動作を比べよ**。
3. **OR-Set のタグの増大**を、測れ。**ガベージコレクション**(全レプリカが、削除を知った、タグを捨てる)を、考え、**なぜ、全レプリカの、知識が、必要か**を、説明せよ。
4. **残高 ≥ 0 の不変条件**を、PN-Counter で、守れない**例**を、作れ。どうすれば、守れるか(調整が、いつ、必要か)。
