**1.** L1 ≈ 1ns、L2 ≈ 4ns、DRAM ≈ 80〜100ns、NVMe ≈ 20〜100µs、DC内往復 ≈ 100〜500µs。

**6.** 1命令あたりのミス損失: 0.2 × (1−精度) × 15。98% → 0.2×0.02×15 = 0.06 サイクル、99% → 0.03 サイクル。理想 0.25 に対して CPI は 0.31 → 0.28。約 **10% の性能向上**。

**8.** ライン数 = 65536/64 = 1024、セット数 = 1024/4 = 256 → index 8 bit、offset 6 bit。

**9.** 仮想アドレスの下位ビットは物理アドレスと同じ(ページ内オフセット)。index+offset がその範囲に収まれば、変換前にセットを選べる。容量 = セット数 × way × 64B = 2^(index+offset) × way なので、2^(index+offset) ≤ ページサイズ から導かれる。

**10.** AMAT = 1 + 0.10 × 13.4 = 2.34 ns。約40%悪化。

**11.** 配列: 連続アクセスをプリフェッチャが検出して先読み。独立なアドレス計算なので OoO が多数のロードを同時発行(MLP)。リスト: 次のアドレスが直前のロード結果に依存するため、プリフェッチも MLP も OoO の先読みも効かず、毎回フルのレイテンシを払う。

**13.** 100GB/s × 90ns = 9000B。9000/64 ≈ 140 ライン。

**14.** M を持つコアがスヌープ要求を検知し、データを供給(またはメモリへ書き戻し)、自身は S へ(読み手と共有する場合)。読み手は S で取得。メモリが古い場合は、dirty データがメモリにも反映される。

**17.** 各コアの store は store buffer に入りキャッシュ/メモリに反映される前に、後続の load が実行される(Store→Load の並べ替え)。防ぐには `mfence`、または `xchg`(seq_cst の store は通常これを使う)。

**19.** データ競合のない(正しく同期された)プログラムは、SC で実行されたかのように振る舞う。プログラマは弱いメモリモデルの詳細を知らなくても、同期の規則を守るだけで安全になる。
