# 第14回 演習

すべて Go(標準ライブラリのみ)。5本は、1つのモジュール(`ex14data`)にまとめてある。macOS(Apple Silicon)で動作を確認した。**Linux での実行は未確認**。

```bash
cd 14-large-scale-data-infrastructure/exercises
go run ./ex1_dynamo_kv
go run ./ex2_merkle_antientropy
go run ./ex3_erasure_coding
go run ./ex4_partitioned_log
go run ./ex5_skew_and_stragglers
```

| 演習 | 実体 |
|---|---|
| ex1 | **分散 KV の簡易版**(一貫性ハッシュの輪、クォーラム、あいまいなクォーラム、ヒント付き引き継ぎ、ベクタークロック、読みの修復)。同期的な、1 プロセス内の模擬。ネットワークの遅延は、なし |
| ex2 | **Merkle 木**の、実際の実装。通信量を数える |
| ex3 | **Reed–Solomon**(GF(256)、Cauchy 行列)の、実際の実装と、マルコフ連鎖による、耐久性の計算 |
| ex4 | パーティションされたログ(Kafka 型)の模擬。順序、配達の保証、並列度 |
| ex5 | A: パーティションの偏り(モンテカルロ)、B: MapReduce 型のジョブと、投機的実行(離散イベントの模擬) |

**実際の GFS、Bigtable、Dynamo、Cassandra、Kafka、Spanner は、使っていない**。数値は、モデルの結果であり、傾向を見るもの。

## 進め方

第1〜13回と同じ。実行前に予想を書き、実行して比べ、外れたら理由を調べる。

**注意**: ex1 は、約 15 秒かかる。他は、数秒。

---

## 演習1: Dynamo 型の KV

[ex1_dynamo_kv/](ex1_dynamo_kv/)

**課題**

1. 厳密なクォーラムと、あいまいなクォーラムで、**k 個のノードが落ちたときの可用性**を、予想し、確かめよ(A)。
2. 古い読みの割合(B)を、**各設定**で予想せよ。**あいまいなクォーラムが、R + W > N なのに、古い読みを許す**理由を、図で説明せよ。
3. **読みの修復**を、(i) 問い合わせた R 個にだけ、(ii) 優先リストの全レプリカに、の 2 通りで、実装し、効果を比べよ(§10 の、つまずき)。
4. **ネットワークの遅延**を、模擬に入れよ(複製が、非同期に届く)。**並行な更新が、自然に起き**(C を、直接作らなくても)、**兄弟の頻度**を、測れ。
5. **発展**: ゴシップによる、メンバーシップと、故障検出(第12回)を、実装せよ。

## 演習2: Merkle 木

[ex2_merkle_antientropy/](ex2_merkle_antientropy/)

**課題**

1. k(食い違いの数)と、葉の数を変えて、**通信量**を、予想し、確かめよ。**最適な葉の数**は、k に、どう依存するか。
2. **木の構築のコスト**(全データの走査)と、**更新のたびの、木の更新のコスト**を、測れ。**通信量の削減**と、比べて、**得か損か**を、判断せよ。
3. **発展**: 葉の中のキーを、**ソートされた範囲**にして、**葉のキーの一覧の交換**を、さらに減らす方法を、考えよ。

## 演習3: イレイジャーコーディング

[ex3_erasure_coding/](ex3_erasure_coding/)

**課題**

1. RS(k, m) の、**符号化と復号**を、実装の中で、追い、**どの k 個からでも復元できる理由**を、**行列の、可逆性**から、説明せよ(Cauchy 行列の、全ての部分行列が、可逆)。
2. **k − 1 個**からでは、復元できないことを、確認せよ。
3. 修復の時間、故障率を変えて、**耐久性**が、どう変わるか、調べよ。**修復の時間が、短いほど、強い**ことを、確かめよ。
4. **相関する故障**(同じラックの、複数のシャードが、一度に落ちる)を、**モデルに入れ**(モンテカルロ)、**シャードを、異なるラックに置く**ことの、効果を、測れ。**独立な故障の、モデルの数値と、どれだけ違う**か。
5. **発展**: **LRC**(Local Reconstruction Codes)の、考え方を、調べ、**修復の読み出しを、k 未満にできる**仕組みを、説明せよ。

## 演習4: パーティションされたログ

[ex4_partitioned_log/](ex4_partitioned_log/)

**課題**

1. パーティション数と、**異なるキーの順序の逆転の割合**の関係を、予想し、確かめよ。
2. コミットの方式(先、後、バッチ)と、**失われる、重複する**メッセージの数を、予想し、確かめよ。**バッチの大きさ**と、重複の関係は。
3. **冪等な処理**の、**状態**(処理済みの id の集合)が、**無限に増える**問題を、どう解決するか。**有効期限**、**単調増加のシーケンス番号**を、考えよ。
4. **キーの偏り**(Zipf)と、パーティション数、コンシューマ数で、**安定か不安定か**を、予想し、確かめよ。**ホットキーの、ソルト**を、ログに適用すると、どうなるか。
5. **発展**: **コンシューマグループの、リバランス**(コンシューマの追加・削除で、パーティションを、再割り当て)の間の、**重複と、遅れ**を、模擬せよ。

## 演習5: 偏りと遅いタスク

[ex5_skew_and_stragglers/](ex5_skew_and_stragglers/)

**課題**

1. 分布(連番、Zipf)と、分割(ハッシュ、範囲、ソルト)の、組み合わせで、**偏り**を、予想し、確かめよ(A)。
2. ソルトの、**分割数**(4、16、64)と、**対象のキー数**(上位 10、100、1,000)を変えて、**偏りと、読みのコスト**の、トレードオフを、調べよ。
3. **遅いワーカーの割合と、遅さ**を変えて、**完了時間**と、**投機的実行の効果**を、予想し、確かめよ(B)。
4. **投機的実行の、起動の閾値**(中央値の 1.3 倍)を、変えて、**完了時間と、追加の仕事**の、トレードオフを、調べよ。**最適な閾値**は、あるか。
5. **データの偏りによる遅さ**(一部のタスクだけ、重い)を、**モデルに入れ**、**投機的実行が、効かない**ことを、確かめよ。**タスクの分割**(重いタスクを、小さく割る)で、解決することを、確かめよ。
