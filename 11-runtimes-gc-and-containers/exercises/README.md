# 第11回 演習

すべて Go(標準ライブラリのみ)。5本は、1つのモジュール(`ex11rt`)にまとめてある。macOS(Apple Silicon)で動作を確認した。**Linux での実行は未確認**。`linux_only/` は、**この Mac では、実行していない**。

```bash
cd 11-runtimes-gc-and-containers/exercises
go run ./ex1_gc_basics
go run ./ex2_gc_latency
go run ./ex3_toy_collectors
go run ./ex4_gomemlimit
go run ./ex5_cfs_throttle_sim
```

| 演習 | 実体 |
|---|---|
| ex1 | **実際の Go ランタイム**(子プロセスを起動して測る)。`GOGC` と、生きているヒープを変える |
| ex2 | **実際の Go ランタイム**。GC の時間と、遅延(タイマーのずれ、処理の遅延) |
| ex3 | おもちゃの GC(配列で表したヒープ)。アルゴリズムの仕事量を数える。実際のランタイムの、実装ではない |
| ex4 | **実際の Go ランタイム**。`GOMEMLIMIT` |
| ex5 | シミュレーション(CFS の帯域制御の、簡易モデル) |
| linux_only | Linux 専用(名前空間、cgroup)。**未実行** |

## 進め方

第1〜10回と同じ。実行前に予想を書き、実行して比べ、外れたら理由を調べる。

**注意(安全のため)**

- ex1、2、4 は、**CPU とメモリを、使い切る**(ex2 は、最大 800 MB のヒープ、ex1 は、`GOGC=400` で、2 GB を超える)。他の作業を止め、メモリに余裕があることを確認してから実行する。
- 結果は、**その時の、マシンの負荷に左右される**。数値の傾向(比)を見る。絶対値は、環境で変わる。
- **Docker は使っていない**。`linux_only/` は、**Linux で、自分が管理するマシン**で実行する。名前空間の演習(`clone`)は、コンテナの外でも、動くが、**他人のマシンや、共有の環境では実行しない**。

## 演習1: GC のコスト

[ex1_gc_basics/](ex1_gc_basics/)

**課題**

1. 実行前に予想する: `GOGC` を 25 から 400 に上げると、GC の CPU 割合、ヒープの最大、割り当て速度は、それぞれ、どちらに、どれだけ変わるか。
2. 生きているヒープを 25 → 100 → 400 MB と変えると、GC の CPU 割合は、どうなるか(§4.3 の式で、予想する)。
3. 実測の、ヒープの最大が、理論値より大きくなる理由を、**仮説として**書け。その仮説を確かめる実験を、設計せよ(例: 割り当ての速度を、変える)。**発展**: 実際に、実行して、仮説を検証せよ。

## 演習2: GC と遅延

[ex2_gc_latency/](ex2_gc_latency/)

**課題**

1. ポインタを含まない 400 MB と、ポインタだらけの 400 MB の、GC 1 回の時間を、予想し、比べよ。
2. STW の停止は、ヒープの大きさで、どう変わるか。なぜか。
3. B の、ポインタだらけの p99(約 20 ms)の原因を、仮説として、書け。`runtime/trace` で、確かめる手順を書き、**実際に確かめよ**(この講義では、未実施)。
4. 割り当てを行う goroutine の数、1 回の割り当ての大きさを、変えて、p99 は、どう変わるか。

## 演習3: おもちゃの GC

[ex3_toy_collectors/](ex3_toy_collectors/)

**課題**

1. マーク & スイープと、コピーの、「触った数」と、時間を、生きている割合ごとに、比べよ。差は、どの割合で、最大になるか。
2. 参照カウントで、**循環を、回収する**仕組み(例: 試験的な削除、循環の検出)を、追加せよ。
3. 世代別 GC のモデルで、**老いた世代 → 若い世代への参照**(書き込みバリアが記録するもの)を、含めた、より現実的なモデルにせよ。コピー量は、どう変わるか。
4. 「95% が、すぐ死ぬ」という仮定を、変えて(例: 50%)、世代別の利点が、どこまで残るか、調べよ。

## 演習4: `GOMEMLIMIT`

[ex4_gomemlimit/](ex4_gomemlimit/)

**課題**

1. 上限を、400 → 80 MiB に、締めたとき、ヒープの最大、GC の CPU 割合、割り当て速度が、どう変わるか、予想し、比べよ。
2. 上限が、生きている量より小さい場合、守れない。なぜ、ランタイムは、アプリを、止めないのか。
3. GC の CPU 割合が、70% を超えた理由を、調べよ(`runtime/metrics` の、`/cpu/classes/gc/` 以下の、内訳を、読め)。**この講義では、未解決**。

## 演習5: CFS 帯域制御のシミュレーション

[ex5_cfs_throttle_sim/](ex5_cfs_throttle_sim/)

**課題**

1. 平均の使用率 30、50、70、90% で、スロットリングされる周期の割合、p99 を、予想し、比べよ。
2. スレッド数 T を増やすと、p99 が、悪化する状況を、**モデルに、追加して**作れ(例: リクエストが、バースト的に、到着する、1 件が CPU バウンドで、長い)。
3. 上限を、200 ms / 100 ms から、20 ms / 10 ms(周期を短く)に、変えると、p99 は、どう変わるか。
4. 実際の Linux で、同じ条件を、再現し、`cpu.stat` の `nr_throttled` と、モデルを、比べよ(`linux_only/` の課題)。
