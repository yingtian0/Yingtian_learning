**3.** システムコールは、権限だけが変わる(約 100 ns)。コンテキストスイッチは、走る実行の流れが変わり、レジスタとページテーブルが入れ替わる(約 1〜数 µs。間接コストを含めるとさらに大きい)。

**7.** 言えること: アドレス空間の切り替えの分が、上乗せされている可能性がある。言えないこと: 純粋な切り替えのコスト。1往復に4回のシステムコールと、macOS ではコアの固定ができないため、別コアを起こす経路が含まれる。Linux で1コアに固定すると、より純粋に測れる。

**9.** `pipe` で2つの fd を作り、a と b を `fork`、それぞれ標準出力と標準入力にパイプの端を付け替えて `exec`。親は両端を閉じる。閉じ忘れると、書き端が残り、b が EOF を受け取れず、終わらない。

**11.** 終了状態(終了コードなど)を、親が `wait` で受け取るまで保持する必要があるため。PID が占有され続け、枯渇すると新しいプロセスを作れない。

**14.** 1回。通常のシグナルは、保留中は1つにまとまる。SIGCHLD のハンドラは、`waitpid(-1, ..., WNOHANG)` を、回収できなくなるまで繰り返す。

**19.** 時刻 0 には L しかいないので、L を選ぶ。SJF は非プリエンプティブなので、走り始めた L を止めない。FCFS と同じになる。

**20.** RR が改善するのは、ターンアラウンドではなく応答時間(40.0 から 2.0 へ、q=1 の場合)。対話的な処理では、最初の反応が早いことが重要。

**24.** 重みの比で 90.3% 対 9.7%。違いの理由: macOS のスケジューラが、nice 値を、Linux と違う方法で優先度に反映するためかもしれない。また、性能コアと効率コアの混在も影響しうる。どちらが原因かは、確認していない。

**30.** `GOMAXPROCS` が 64 のままだと、64 スレッドが同時に走って、CPU クォータを一気に使い切り、周期の残りの間、全スレッドが止められる(スロットリング)。確認: cgroup の `cpu.stat` の `nr_throttled`。対策: `GOMAXPROCS` をクォータに合わせる(Go 1.25 以上の言語バージョンなら、既定で考慮される)、または、クォータの上限を見直す。

**31.** load average は、実行可能なプロセスと D 状態(ディスク I/O などの中断できない待ち)の両方を数える。D が多ければ、原因は I/O。`ps` の STAT を見て、種類を分ける。
